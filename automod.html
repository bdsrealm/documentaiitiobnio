Chapter ten

Anticheat and automod

A realm cannot run a plugin, but it can hold a second player. That player decodes the same packets, keeps a score per identity, and enforces through the commands an operator already has: /kick and /ban. This chapter builds one end to end.

An automod with operator is a loaded gun pointed at your own member list. Run it in --dry first, keep an audit log, and only give it an account you control on a realm you own. Never point it at someone else's world.

10.1 The shape of the thing

Everything here is one long-lived client with four jobs: join like any player, read what the realm broadcasts, score each identity over time, and act through operator commands. There is no server hook to install and no privileged socket — the automod sees exactly what a normal member sees.

JobUsesFrom
Joinauth flow, realm resolve, NetherNet / RakNet connectsrc/bot.js, src/engine/
Readtext, player_list, add_player, move_player, animate, entity_event, block_actor_datathe engine's packet events
Scoreper-identity weights, decay, thresholdsthis chapter
Actcommand_request as /kick / /banengine.command()

Because the client already installs the inbound guard from chapter 9, the automod's listeners never see a NaN position, a 4 000-newline text or a 200 kB NBT blob — those are dropped upstream of emit. That is deliberate: the moderator bot should not be crashable by the thing it moderates. The trade-off is that it also cannot report every crash attempt, so the guard's counters (the anticrash: line of status) are the other half of the picture.

10.2 The account, the invite, the op

  1. Dedicated account. Not your main. It needs its own Microsoft account, its own profiles/ cache entry, and its own gamertag — members will see it in the list and it should read as staff.
  2. Join the realm. Invite it from the realm's member screen, or accept an invite link. The bot resolves the invite to a NetherNet address exactly as chapter 6 describes.
  3. Get operator. The realm owner runs /op <botname> in game (or toggles Operator on the member in Realm settings). No packet the bot can send replaces this — permission is granted by the owner, not claimed by the client.
  4. Verify. await bot.engine.command('/list') should answer with the player list. If it answers unknown command or nothing, the op did not land and /ban will silently fail too.

A second account is also a second member slot. On a 10-player realm the automod permanently occupies one, and on a full realm it cannot join at all. Check maxPlayers before designing around it.

10.3 Wiring into the stream

The bot object exposes the live client as bot.engine.client once it has spawned. Attach listeners there — after connect(), before you need them. 

const { Bot } = require('./src/bot')
const { createAuthflow, authenticate } = require('./src/auth')
const { makeBxAuthflow } = require('./src/engine/bedrockx')

const flow = createAuthflow(cfg.account)
const bxFlow = makeBxAuthflow(cfg.account, (code) => {
  console.log(`sign in: ${code.verification_uri} — ${code.user_code}`)
})

const bot = new Bot(cfg, flow, bxFlow)
bot.profile = await authenticate(flow)
await bot.connect()                       // uses cfg.realm

const client = bot.engine.client          // packet events live here
const selfId = bot.engine.runtimeId       // never score yourself

client.on('text', onText)
client.on('player_list', onPlayerList)
client.on('move_player', onMovePlayer)
client.on('animate', onAnimate)
client.on('entity_event', onEntityEvent)
client.on('block_actor_data', onNbt)

Sending is symmetrical: bot.say() for chat, and bot.engine.command('/kick …') which resolves with the command's output text — the only reliable way to know the ban actually happened.

10.4 Who you are scoring

Bots rotate names, so the key matters more than the label. Three identifiers appear in the stream, and they are not equally trustworthy:

KeyComes fromStabilityUse it for
xuidtext.xuid, player_list.xbox_user_idstable per accountscores, bans, evidence
uuidplayer_list records, add_player.uuidstable per accountcorrelating list ↔ entity
runtime_idadd_player, move_player, animateper session onlymovement gait, not bans
source_nametextmutable, spoofabledisplay and fallback only

A ban command takes the name, because that is what the server resolves. So keep a map from xuid to the last name you saw, and ban by the name while the record is fresh — a bot that leaves and renames is a different ban target anyway.

10.5 What is worth detecting

The bot in this repo already has a detector worth copying: botdet counts packets per entity per second, flags rate anomalies, and pattern-matches the spam families it has seen — /me floods, /tell loops, and the * External prefix relay bots use when they echo another realm's chat. Its thresholds are the starting point below.

Bot gait is the most reliable antibot signal available to a client, and the least certain. A scripted walker holds a fixed speed, never changes yaw, never jumps, and sends one move per tick. Measure the standard deviation of horizontal step length over ~20 packets; a human's is never that flat. Two flat walkers joining together is the pattern worth acting on — one is probably a person on autopilot.

10.6 Score, decay, enforce

Never act on a single packet. Add weight, decay it, and act on thresholds — that is what keeps a lag spike from banning someone. 

const WEIGHT = {
  chatRate: 3, repeat: 2, relaySpam: 2, meSpam: 3,
  animate: 2, moveRate: 2, commandRate: 4, eventRate: 3,
  nbtBomb: 10, textBomb: 10, badFloat: 10,
  botGait: 3, joinBurst: 5
}
const LIMIT = { kick: 12, ban: 24, decayPerMinute: 1 }

Then the ladder: 0–11 watch, 12+ kick, 24+ ban. Warn once at 6 so a person who is just loud gets a message before anything happens to them, and always prefer a kick to a ban when the evidence is behavioural rather than mechanical.

10.7 The full automod

One file, no dependencies beyond this repo. Save as automod.js next to config.json, run with REALM=<invite|id> node automod.js --dry until the log looks sane, then drop --dry. 

'use strict'
// automod.js — a second client in the realm that scores and bans.
//   REALM=<invite|id> node automod.js [--dry]

const fs = require('fs')
const path = require('path')
const crypto = require('crypto')
const { Bot } = require('./src/bot')
const { createAuthflow, authenticate } = require('./src/auth')
const { makeBxAuthflow } = require('./src/engine/bedrockx')

const DRY = process.argv.includes('--dry')
const AUDIT = path.join(__dirname, 'automod-audit.jsonl')

const W = {
  chatRate: 3, repeat: 2, relay: 2, me: 3, animate: 2, moveRate: 2,
  commandRate: 4, event: 3, nbt: 10, textBomb: 10, badFloat: 10,
  gait: 3, joinBurst: 5
}
const T = { kick: 12, ban: 24, decay: 1 }

/* ── state ─────────────────────────────────────────────────────────── */
const scores = new Map()      // xuid|name -> { score, name, reasons, last }
const buckets = new Map()     // key -> { count, start }
const lastMsg = new Map()     // name -> [{ hash, ts }]
const gait = new Map()        // runtime_id -> [step lengths]
const joins = []              // { name, ts }
const actedAt = new Map()     // name -> ms of last action

function who (p) {
  return { name: p.source_name || p.username || 'unknown', xuid: p.xuid || p.xbox_user_id || '' }
}
function keyOf (w) { return w.xuid || w.name }

function bump (w, weight, reason) {
  const k = keyOf(w)
  const s = scores.get(k) || { score: 0, name: w.name, reasons: [], last: Date.now() }
  s.score += weight
  s.name = w.name !== 'unknown' ? w.name : s.name
  s.reasons.push(reason)
  if (s.reasons.length > 24) s.reasons.shift()
  s.last = Date.now()
  scores.set(k, s)
  return s
}

function rate (key, windowMs, limit) {
  const now = Date.now()
  const b = buckets.get(key)
  if (!b || now - b.start > windowMs) { buckets.set(key, { count: 1, start: now }); return false }
  b.count++
  return b.count > limit
}

function hash (s) { return crypto.createHash('sha1').update(s).digest('hex').slice(0, 12) }

/* ── enforcement ───────────────────────────────────────────────────── */
async function act (s, why) {
  const ban = s.score >= T.ban
  const cmd = ban ? `/ban "${s.name}"` : `/kick "${s.name}" automod: ${why}`
  const line = { ts: new Date().toISOString(), name: s.name, score: s.score, why, cmd }

  if (DRY) {
    console.log('[dry]', line.ts, s.name, s.score, '→', cmd)
    return
  }
  const last = actedAt.get(s.name) || 0
  if (Date.now() - last < 60_000) return
  actedAt.set(s.name, Date.now())

  try {
    line.output = await bot.engine.command(cmd)
  } catch (err) {
    line.output = 'error: ' + err.message
  }
  fs.appendFileSync(AUDIT, JSON.stringify(line) + '\n')
  console.log('[automod]', line.ts, s.name, s.score, '→', cmd, '|', line.output)
  await bot.say(`[automod] ${s.name} ${ban ? 'banned' : 'kicked'} (score ${s.score})`)
}

/* ── packet handlers ───────────────────────────────────────────────── */
function onText (p) {
  const msg = String(p.message || '')
  const w = who(p)
  if (!p.xuid && !p.source_name) return          // system / server line

  if (/\uF8FF{8,}|\n{8,}/.test(msg)) bump(w, W.textBomb, 'text bomb')
  if (/^\s*\*?\s*External\b/i.test(msg)) bump(w, W.relay, 'relay spam')
  if (/^\s*\/me\b/i.test(msg) || /^\s*\*\s*\S+\s+/.test(msg)) bump(w, W.me, '/me spam')

  if (rate('chat:' + keyOf(w), 1000, 5)) bump(w, W.chatRate, 'chat rate')

  const h = hash(msg.replace(/\s+/g, ' ').trim().toLowerCase())
  const hist = (lastMsg.get(w.name) || []).filter((x) => Date.now() - x.ts < 30_000)
  hist.push({ hash: h, ts: Date.now() })
  lastMsg.set(w.name, hist.slice(-8))
  if (hist.filter((x) => x.hash === h).length >= 4) bump(w, W.repeat, 'repeat spam')

  const s = scores.get(keyOf(w))
  if (s && s.score >= T.kick) act(s, s.reasons.slice(-3).join(', '))
}

function onPlayerList (p) {
  const records = p.records?.records || p.entries || p.records || []
  const now = Date.now()
  const names = new Set(records.map((r) => r.username).filter(Boolean))
  const fresh = [...names].filter((n) => !joins.some((j) => j.name === n && now - j.ts < 120_000))
  for (const n of fresh) joins.push({ name: n, ts: now })
  if (joins.length > 200) joins.splice(0, joins.length - 200)

  const recent = joins.filter((j) => now - j.ts < 5_000)
  if (recent.length > 3) for (const j of recent) bump({ name: j.name }, W.joinBurst, 'join burst')

  for (const n of fresh) {
    if (/^[A-Za-z]{4,}\d{3,}$/.test(n) || /^[a-z]{6,}[0-9]{2}$/i.test(n)) {
      bump({ name: n }, 1, 'scripted name')
    }
  }
}

function onMovePlayer (p) {
  const id = p.runtime_id ?? p.runtime_entity_id
  if (id === undefined || id === selfId) return
  const pos = p.position
  if (!pos) return
  if ([pos.x, pos.y, pos.z].some((v) => typeof v !== 'number' || !isFinite(v))) {
    const name = bot.entities.get(String(id))?.name || `rtid_${id}`
    bump({ name }, W.badFloat, 'bad floats')
    return
  }

  const prev = gait.get(id) || { last: null, steps: [] }
  if (prev.last) {
    const dx = pos.x - prev.last.x, dz = pos.z - prev.last.z
    prev.steps.push(Math.hypot(dx, dz))
    if (prev.steps.length > 24) prev.steps.shift()
  }
  prev.last = { x: pos.x, z: pos.z }
  gait.set(id, prev)

  if (prev.steps.length === 20) {
    const mean = prev.steps.reduce((a, b) => a + b, 0) / prev.steps.length
    const sd = Math.sqrt(prev.steps.reduce((a, b) => a + (b - mean) ** 2, 0) / prev.steps.length)
    const name = bot.entities.get(String(id))?.name || `rtid_${id}`
    if (mean > 0.05 && sd < 0.01) bump({ name }, W.gait, 'bot gait')
  }

  if (rate('move:' + id, 1000, 50)) {
    bump({ name: bot.entities.get(String(id))?.name || `rtid_${id}` }, W.moveRate, 'move rate')
  }
}

function onAnimate (p) {
  const id = p.runtime_entity_id ?? p.runtime_id
  if (id === undefined || id === selfId) return
  if (rate('animate:' + id, 1000, 20)) {
    bump({ name: bot.entities.get(String(id))?.name || `rtid_${id}` }, W.animate, 'animate spam')
  }
}

function onEvent (p) {
  const id = p.runtime_entity_id ?? p.runtime_id
  if (id === undefined || id === selfId) return
  if (rate('event:' + id, 1000, 30)) {
    bump({ name: bot.entities.get(String(id))?.name || `rtid_${id}` }, W.event, 'event spam')
  }
}

function onNbt (p) {
  if (!p.nbt) return
  let size = 0
  try { size = JSON.stringify(p.nbt).length } catch { size = 1e9 }
  if (size > 100_000) bump(who(p), W.nbt, 'nbt bomb')
}

/* ── decay loop ────────────────────────────────────────────────────── */
setInterval(() => {
  const now = Date.now()
  for (const [k, b] of buckets) if (now - b.start > 120_000) buckets.delete(k)
  for (const [k, s] of scores) {
    const mins = Math.floor((now - s.last) / 60_000)
    if (mins >= 1) { s.score = Math.max(0, s.score - mins * T.decay); s.last = now }
    if (s.score === 0) scores.delete(k)
  }
}, 15_000)

/* ── boot ──────────────────────────────────────────────────────────── */
let bot, selfId

;(async () => {
  const cfg = JSON.parse(fs.readFileSync(path.join(__dirname, 'config.json'), 'utf8'))
  cfg.realm = process.env.REALM || cfg.realm
  cfg.account = cfg.account || {}
  cfg.account.profilesFolder = path.resolve(__dirname, cfg.account.profilesFolder || './profiles')

  const flow = createAuthflow(cfg.account)
  const bxFlow = makeBxAuthflow(cfg.account, (c) => console.log(`sign in: ${c.verification_uri} ${c.user_code}`))

  bot = new Bot(cfg, flow, bxFlow)
  bot.profile = await authenticate(flow)
  await bot.connect()

  const client = bot.engine.client
  selfId = bot.engine.runtimeId
  client.on('text', onText)
  client.on('player_list', onPlayerList)
  client.on('move_player', onMovePlayer)
  client.on('animate', onAnimate)
  client.on('entity_event', onEvent)
  client.on('block_actor_data', onNbt)

  console.log(`automod online as ${cfg.account.username}${DRY ? ' (dry run)' : ''}`)
  await bot.engine.command('/list')
})().catch((err) => {
  console.error('automod failed to start:', err?.message || err)
  process.exit(1)
})

bot.entities is the bot's own runtime-id → player map, maintained by its add_player / player_list listeners. It is how a move_player packet becomes a name you can ban.

10.8 Getting it operational

  1. Dry run for a day. --dry prints the action it would take and writes nothing. Read the log: if a real member is sitting at 15 points, your weights are wrong, not the member.
  2. Staff account hygiene. The automod's token lives in profiles/ next to any other account's. Treat that folder like a password store; never commit it.
  3. Supervise the process. A moderation bot that dies quietly is worse than none — run it under a supervisor with the same reconnect backoff the bot already implements, and alarm if it has been offline for more than a minute.
  4. Keep the audit file. Every action appends one JSON line: time, name, score, command, output. It is the only thing that settles "why was I banned".
  5. Two operators. If the automod is the only op, a false positive can lock the owner out of their own realm. Keep a human op as a break-glass.

10.9 What it cannot do

LimitationWhyWhere it belongs instead
Stop a pre-join floodIt only sees the realm after it is insidehost-side handshake and connection caps
Ban an IPRealm commands take names, not addressesserver ACLs; on Realms, report and rotate the invite
Delete spam already sentChat has no retraction packetprevention — kick before it repeats
See whispers to other playersThe realm only broadcasts what it choosesnothing; accept the blind spot
Stop a determined multi-account attackerEach new account starts at zero scorejoin-signature clustering plus manual invites
Protect itself from a hostile serverIt is a clientthe inbound guard, § 9.10

The honest summary: an automod is a behavioural filter with a ban command attached. It is excellent against the 90% of abuse that is lazy and repetitive, and useless against a patient human who types slowly. Design it to escalate to a human, not to replace one.
