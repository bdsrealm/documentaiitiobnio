Chapter eight

Rewriting the client

A Bedrock client is five small programs wearing one trench coat: an authenticator, a transport, a codec, a session state machine and a tick loop. Most of the pain in this codebase comes from those five things living inside one 215-line class.

8.1 Five layers, five contracts

LayerOwnsMust not know about
AuthXbox tokens, Bedrock session, key pairpackets, sockets
Transportordering, reliability, MTU, reconnectsBedrock packet names
Codecbytes ⇄ { name, params }sockets, auth, timing
Sessionstate machine, handshake, crypto, spawnhow the UI works
Tick20 Hz loop, input, movement, batchingtransport internals

The interfaces are small enough that they fit on one screen, which is the test: if a layer needs four callbacks into another, they are the same layer. 

// transport: bytes in, bytes out, one lifecycle
interface Transport {
  connect(): Promise<void>
  send(buf: Buffer): void                 // one Bedrock batch
  on(event: 'message' | 'close' | 'error'): void
  close(reason?: string): void
}

// codec: version-pinned, stateless, no global mutable state
interface Codec {
  encode(name: string, params: object): Buffer
  decode(buf: Buffer): { name: string, params: object }
  ids: Map<string, number>
}

// crypto: one object per direction, explicit counters
interface Cipher {
  seal(plaintext: Buffer): Buffer
  open(ciphertext: Buffer): Buffer        // throws on tamper
}

8.2 What not to copy from this code

DecisionWhy it hurtsBetter
AES-GCM used as a keystream, integrity from a truncated SHA-256 counter checksum The GCM tag is never written or checked; the checksum is custom and both ends must agree on counter state forever. Pick one real construction and use it fully — GCM with its tag, or the CFB8 + checksum scheme the vanilla client uses. Do not hybridise.
Static key for NetherNet discovery (SHA-256(LE64(0xdeadbeef))) No secrecy, no authentication — it only stops casual sniffing. Fine for LAN beaconing if documented as obfuscation; never used as the security boundary (DTLS is). Say so in the code comment.
Every write() becomes its own batch and its own transport send A flood of 1 000 small packets becomes 1 000 frames, each with its own compression and header. Also no backpressure. Queue packets, flush once per tick or at a size cap, expose an explicit flush().
Codec state in a global variable (ShieldItemID) Two clients in one process share it; item stacks encode differently depending on who joined last. Pass learned ids into the codec instance; build a codec per session.
Version constants repeated in three files Upgrading is a scavenger hunt, and a partial bump produces unreadable parse errors. One version manifest per protocol release; the codec and the login payload read from it.
Filtering WebRTC answers with a patch in the peer (connectionId compare) Correct, but it lives at the wrong layer: the signalling client should only deliver messages addressed to its own connection. Route by connectionId in the signalling layer; keep the peer dumb.
write() catches serializer errors and logs them Callers believe a packet was sent when it was not. This is the single most common "nothing happened" bug. Throw, or return a result object. Let the loop decide whether a bad payload is fatal.
One class doing auth, socket, codec and handshake Cannot test the handshake without a network, cannot swap transport without touching crypto. Compose the five layers; test each against a fake of the one below.

8.3 A session that is a state machine, not a pile of callbacks

const State = {
  idle: 0, connecting: 1, authed: 2, spawned: 3, closed: 4
}

class Session {
  #state = State.idle
  #pending = []

  transition (next, why) {
    if (next === this.#state) return
    const prev = this.#state
    this.#state = next
    this.emit('state', { prev, next, why })

    if (next === State.authed) this.flushPending()
    if (next === State.spawned) this.startTick()
    if (next === State.closed) this.stopTick()
  }

  // writes are refused, not silently dropped, before the state allows them
  write (name, params) {
    if (this.#state < State.authed) throw new Error(`write ${name} before authed`)
    this.codec.encode(name, params)   // throws on a bad payload
    this.transport.send(this.framer.add(name, params))
  }
}

Note the difference from this codebase: early writes are an error instead of a queue that nobody drains, and the parser exception is not swallowed inside the send path.

8.4 Batches at tick rate, not per packet

class Framer {
  constructor ({ threshold = 512, level = 6, header = 0xfe } = {}) {
    this.threshold = threshold
    this.level = level
    this.header = header
    this.pending = []
  }

  add (encoded) { this.pending.push(encoded) }        // varint-length-prefixed

  flush () {
    if (!this.pending.length) return null
    const body = Buffer.concat(this.pending)
    this.pending.length = 0

    const compressed = body.length > this.threshold
    const payload = compressed ? deflateRaw(body, this.level) : body
    const compressionByte = compressed ? 0x00 : 0xff

    return Buffer.concat([Buffer.from([this.header, compressionByte]), payload])
  }
}

Two rules make this safe: a packet is never split across flushes, and the flush never exceeds the transport's MTU budget. On RakNet that budget is ~1400 bytes per datagram after headers; on NetherNet it is the 50 000-byte data-channel segment.

Compression happens after concatenation, which is the whole point: twenty chat lines compress together far better than twenty individual frames. The current code compresses every frame on its own.

8.5 Codec: generated, pinned, replaceable

The best decision in the existing code is compiling protocol.json with protodef instead of hand-writing encoders. Keep that, and make the version explicit: 

protocols/
  1.26.60/
    schema.json          # 444 types, 254 packets, id mapper
    codec.ts             # generated: encode/decode + name↔id tables
    manifest.json        # { gameVersion, protocolVersion, sha256(schema) }
  index.ts               # registry: protocolFor('1.26.60') → codec

// one codec per session, no globals
const codec = protocolFor(manifest.gameVersion).createCodec({ variables: {} })
codec.setVariable('ShieldItemID', 355)

Generated code can also expose per-packet TypeScript types and a requiredFields(name) helper — which is what turns "packet silently ignored" into a compile error or a clear runtime message.

8.6 The tick loop is a first-class component

class Loop {
  constructor (session, { hz = 20 } = {}) {
    this.period = 1000 / hz
    this.tick = 0n
    this.drift = 0
    this.session = session
  }

  start () {
    this.next = performance.now()
    this.timer = setInterval(() => this.run(), this.period / 2)  // check at 2× rate
  }

  run () {
    const now = performance.now()
    if (now < this.next) return
    this.drift = now - this.next
    this.next += this.period

    if (this.drift > this.period * 2) this.next = now + this.period  // stop spiralling

    this.session.onTick(this.tick++)   // input → player_auth_input → flush
  }

  stop () { clearInterval(this.timer) }
}

A 2× interval check keeps the loop from drifting without ever sending two ticks in the same millisecond. If you want exactness, drive the loop from the socket's event loop and use tick_sync to measure the error.

8.7 How you know it works

  1. Golden vectors. Encode a known packet, compare against a stored hex fixture. This is the only way to catch a field order change after a version bump.
  2. Round-trip corpus. Record real packets from a join, decode → encode → decode, and require byte equality. Catches mapper and NBT mistakes that a spec reading will not.
  3. Loopback server. The engine ships a server implementation; run client against it in CI with a fake auth. The full handshake, encryption and spawn sequence then take milliseconds instead of a realm join.
  4. Fuzz the codec. Random buffers into the parser must produce parse errors, never crashes or unbounded allocations. This is exactly what the anticrash guard exists because of.
  5. Two clients, one account. The NetherNet signalling fan-out bug only appears with concurrent connections. Make that a test, not a bug report.
  6. Version matrix. Keep at least one older schema and assert that a mismatched protocol version fails at login with a readable error, not a parse storm.

8.8 Performance, measured not guessed

There are no benchmark numbers on this page on purpose. If you rewrite for speed, measure these five things first, because they are where the time goes:

MetricWhy
batches/sec and bytes/packetPer-write batching shows up immediately as a 2–5× byte overhead on small packets.
GC time under a floodEvery Buffer.concat allocates; a 1 MB payload rebuilt per tick is a GC benchmark in disguise.
compress/decompress time per batchDeflate dominates once batches are large; level 6 is not always the right trade.
codec compile time at startupProtodef compilation is not free; it belongs at build time, not per client.
tick jitter (p50/p99)The number that decides whether the server believes you are a player.

8.9 A migration order that does not break the bot

  1. Extract the codec behind a factory first. No behaviour change, but it kills the global ShieldItemID and gives you a place to pin versions.
  2. Add the batching framer with a flag. Measure bytes/sec before and after; keep the per-write path until the numbers agree.
  3. Move signalling routing into the signalling client, then delete the answer-filter patch.
  4. Replace the write-error swallow with a thrown error, and fix the call sites the compiler or tests point at.
  5. Add the tick loop and movement as new modules — nothing else needs to know about them.
  6. Only then split the session class into auth / session / transport files.
  7. Keep the old client runnable until the new one passes the loopback + corpus suite; two transports are cheap, two half-working clients are not.

None of this changes the account rules. A better client is still a client: on realms you do not own or have permission to automate, using it is a ban risk and, in most cases, a terms of service violation. Build against your own server first.
